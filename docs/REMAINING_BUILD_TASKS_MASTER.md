- [ ] تسعير كل قطاع وكل إضافة من قواعد الإدارة المنشورة فقط، والتحقق خادميًا من الأسعار والكميات والصلاحية قبل تسجيل الطلب.

- [ ] نقل اختيارات الضيف إلى الحساب بناءً على موافقة صريحة وتحديد المشروع المستهدف، مع منع الاختلاط على الأجهزة المشتركة.
- [ ] عزل المستندات والشعارات والمعاينات والعقود والدفعات بتفويض قائم على هوية صاحب المشروع، لا تطابق البريد فقط.
- [ ] دعم حفظ تلقائي، نسخ إصدارات، استعادة وإكمال المسودة بعد تسجيل الخروج أو تغيير الجهاز.
**القبول:** عميل لديه مشروعان مستقلان ويستكملهما من مسارين/جهازين دون تسريب أو تبديل للبيانات، مع اختبارات منع الوصول لحساب آخر.

- [ ] تطبيق اسم النشاط والشعار والألوان والخطوط والنصوص والوسائط والإضافات على معاينة تخص مشروعًا معينًا.
- [ ] حفظ رابط معاينة خاص وإصدارات وتعديلات العميل وسجل التعليقات والقبول النهائي لكل مشروع.
- [ ] عدم تحويل «معاينة مقبولة» إلى «تسليم فعلي» دون استكمال العقد/استحقاق الدفع.
**القبول:** تخصيص وحفظ ومراجعة واعتماد نسختين مختلفتين لمشروعين للعميل نفسه؛ نجاح سيناريو الموبايل والكمبيوتر.

### ATSH-004 — **تعديل صياغة العقود بالكامل من لوحة الإدارة** [طلب جديد — إلزامي]
**الموجود:** شاشة إنشاء قالب عقد من لوحة المبيعات، وواجهة قراءة قوالب من الـAPI، ولقطة `body_snapshot` عند إصدار عقد؛ **لا توجد حتى الآن واجهة تحرير محفوظ لقالب موجود.**
- [ ] صفحة واضحة في لوحة الإدارة: **العقود ← إدارة صيغ العقود**، تشمل عرض القوالب، البحث، إنشاء، فتح، تعديل النصوص والبنود وترتيبها، حفظ مسودة، معاينة قبل النشر، تنشيط/إلغاء تنشيط، استنساخ وأرشفة.
- [ ] قوالب منفصلة حسب **اشتراك شهري/سنوي** و**شراء الكود/الترخيص** و**الاستضافة المستقلة**، مع شروط الدومين والدعم والملكية الفكرية والضمان والتجديد والإلغاء.
- [ ] محرر متغيرات آمنة لحقول الطلب الموثقة فقط (العميل، المشروع، البنود والأسعار والضرائب، طريقة التسليم، الدعم، المدة)، مع عرض المستند النهائي قبل اعتماده.
- [ ] **إدارة إصدارات قانونية:** كل تعديل على قالب منشور ينشئ إصدارًا جديدًا؛ العقود المُصدرة/الموقعة تبقى مثبتة بنصها وإصدارها ولا تتغير بأثر رجعي؛ لا تعديل مباشر لعقد موقّع.
- [ ] صلاحيات: المالك/المخول يحرر وينشر؛ الأدوار الأقل تستعرض حسب الصلاحيات؛ كل تعديل موثق بالسجل (المستخدم، التوقيت، الملخص، الإصدار).
- [ ] إصدار عقد محدد من عرض سعر معتمد ومعاينة مقبولة وربطه بمشروع العميل الصحيح، وسجل توقيع/إثبات موافقة وإشعار ونسخة PDF.
- [ ] مراجعة قانونية مصرية لمزود وآلية التوقيع الإلكتروني وشروط صحة التعاقد قبل الإنتاج.
**القبول:** يحرر المالك قالبًا منشورًا من لوحة التحكم ويصدر نسخة جديدة، ويظل عقد عميل سابق موقعًا دون تغيير، ثم يصدر عقد عميل آخر بالصياغة الجديدة؛ اختبار صلاحيات وسجل تدقيق ومخرجات PDF.
**ملاحظة:** **هذا متطلب بناء لم ينفذ بعد**. لا يكفي إدخال النص عند إنشاء قالب جديد.

### ATSH-005 — إغلاق دورة العقود ثم الدفع الموثوق
- [ ] ربط `quote version → preview approval → contract version → signature evidence → invoice → verified payment → entitlement` بعلاقة واضحة ومغلقة الصلاحيات.
- [ ] تكامل مزود دفع ومراجعة `webhook` بتوقيع/مرجع فريد ومنع التكرار واسترجاع الحالات والاسترداد.
- [ ] آلية إدارة الاشتراكات الشهرية/السنوية والفواتير ومواعيد التجديد والتعليق والإلغاء.
- [ ] لا يتحول الطلب إلى `paid` باستجابة عميل أو callback غير موثق.
**القبول:** اختبارات نجاح/فشل/إلغاء/تكرار/دفع جزئي وتوقيع عقد قديم/منتهي؛ لا تسليم دون تحقق مستقل.

- [ ] ربط كتالوج القطاع بإضافاته وأسعاره في المحرك دون كسر أسعار أو عقود قديمة.
