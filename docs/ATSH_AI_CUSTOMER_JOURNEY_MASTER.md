# ATSH AI — المرجع الثابت لرحلة العميل
**ID:** ATSH-CUSTOMER-JOURNEY-001 | **الإصدار:** 1.0 | **الحالة:** متطلبات تنفيذ، لا تعني اكتمال الوظائف.

## مبدأ أساسي
المنصة تبدأ بمساعد ذكي يرشّد الزائر حتى التسليم. لا تُلغى الباقات أو محرك التسعير أو المعرض أو وظائف الإدارة عند تحديث التصميم. تبنى المنصة وتُختبر أولًا على GitHub؛ يُؤجّل ربط الدومين والاستضافة وPostgreSQL وn8n والدفع إلى ما بعد اكتمالها وموافقة المالك.

## المسار الإلزامي
**زائر → استقبال المساعد → معرض القطاعات والباقات → اختيار نموذج/خدمة → الإضافات ومحرك التسعير → إنشاء حساب → معاينة تفاعلية مخصصة → اعتماد العرض → توقيع عقد إلكتروني → دفع مؤكّد → تنفيذ وتسليم → دعم ومتابعة.**

### 1. الاستقبال والمساعد
- ترحيب عربي RTL ملائم للموبايل؛ مساعد متاح منذ الصفحة الأولى، يسأل عن المجال والاحتياجات ويقترح القطاع والباقات والكتالوج، مع تصفح حر.
- الإجابات واقتراحات الأسعار مستندة إلى بيانات الكتالوج الفعلية؛ لا أسعار أو وعود مختلقة.
### 2. المعرض
- كتالوج متوسع قابل للإدارة والبحث والفلترة، أكبر كثيرًا من النماذج المرفقة.
- بطاقة لكل نموذج تتضمن القطاع والميزات واللوحات والصور والفيديو ورابط معاينة تفاعلية ووضع الجاهزية.
- المرفقات الحالية أمثلة فقط: **عيادتي** (مرضى ومواعيد وروشتات وفواتير)، **أفوكاتو** (قضايا وموكلون وجلسات وأتعاب وفريق)، **سوبر ماركت** (POS ومخزون ومبيعات وموردون)، **أجزخانة** (POS وأدوية ومشتريات وتقارير). هذه نماذج HTML تجريبية غير متصلة بإنتاج؛ لا تُقدَّم كنظم مكتملة.
### 3. الطلب والتسعير الديناميكي
- اختيار نموذج/قطاع ونوع المشروع وباقة الأساس؛ ثم خيارات منفصلة ومفصلة: الصفحات واللغات والخصائص واللوحات والتكاملات، **الدومين**، **الاستضافة**، **الهوية البصرية**، **المحتوى النصي والمرئي**، **المساعد الذكي الخاص بالعميل**، **الدعم لمدة سنة حسب العرض وشروطه**، الصيانة، وخصائص القطاع.
- كل إضافة سعر مستقل وقاعدة حساب قابلة للتعديل من لوحة الإدارة. عرض سعر حي بندي يفصل التأسيس/الشراء مرة واحدة عن الاشتراك أو التجديد الشهري/السنوي والضرائب والتكاليف المتغيرة. العنصر غير المسعّر «عرض مخصص»، لا يُعد مجانيًا.
- بحث الدومين **حقيقي عبر API مسجّل** عند الربط لاحقًا، يظهر السعر والتوافر اللحظي دون وعد بالحجز؛ إعادة تحقق عند إتمام الشراء. أثناء التطوير تُوسم المحاكاة بوضوح.
- خيار الاستضافة لدى ATSH AI أو لدى العميل أو لاحقًا، مع تكاليف وتفاصيل إدارة وتجديد معلنة.
- المساعد الخاص بالعميل بند اختياري بتكلفة تهيئة منفصلة عن استهلاك API وخطة الدعم.
- حفظ نسخة أسعار واختيارات الطلب وإصدار العرض ورقمه وصلاحيته؛ أي تغيير لاحق مؤثر بالسعر يحتاج إعادة موافقة.
### 4. حساب العميل
- تسجيل/دخول قبل المعاينة المخصصة والشراء، مع استكمال المسودة والملفات والاختيارات بدون فقد.
- صفحة عميل فيها الطلبات والموافقات والمعاينات والعقود والمدفوعات والتنفيذ والتسليم والاشتراكات والتذاكر.
### 5. المعاينة التفاعلية الشخصية
- المعاينة تُظهر نموذجًا مختارًا بشعار العميل وألوانه ونصوصه وصوره والإضافات المتفق عليها، بواجهات موبايل وكمبيوتر وتفاعلات حقيقية أو محاكاة موسومة، دون بيانات عملاء حقيقية.
- يرسل العميل تعديلات ويعتمد معاينة ونطاقًا محددًا؛ التغييرات المؤثرة على السعر تُعيد إصدار العرض.
### 6. العقود الإلكترونية
- اختيار واضح بين (أ) اشتراك شهري/سنوي وخدمة مُدارة أو (ب) شراء/ترخيص الكود مع استضافة منفصلة.
- عرض شروط الملكية والترخيص وحدود الدعم والاستضافة والدومين والتجديد، ومواصفات المشروع والتسليم والرسوم.
- توقيع على إصدار عقد محدد مرتبط بعرض سعر مع سجل موافقة وبصمة المستند والوقت والأطراف، ومزوّد توقيع متوافق قانونيًا قبل الإنتاج.
### 7. الدفع
- بعد توقيع العقد يُصدر طلب دفع وفاتورة؛ لا انتقال إلى «مدفوع» إلا بتأكيد خادمي موثوق من مزود الدفع (Webhook موثق)، مع دعم الفشل والتكرار والإلغاء والاسترداد.
### 8. التنفيذ والتسليم
- بعد تأكيد الدفع يُنشأ المشروع ويبدأ التنفيذ وفق شروط الدفعات؛ توثق المراحل والاعتماد النهائي.
- **استضافة/اشتراك لدى ATSH AI:** لوحة إدارة العميل واشتراكه وتجديده ودعمه.
- **شراء/ترخيص الكود:** تسليم آمن للمصدر والمخرجات والتراخيص المتفق عليها، واستضافة منفصلة اختياريًا. لا يُسلّم كود غير مرخّص ولا تُكشف مفاتيح سرية.
- حالة التسليم موثقة، مع بداية الضمان والدعم والتجديد وإدارة التذاكر.

## لوحة الإدارة المركزية
إدارة الخدمات والقطاعات والقوالب والمعرض والوسائط، المحتوى والمظهر، الباقات والإضافات والأسعار والضرائب، إعدادات المساعد، العملاء والطلبات والفرق والأدوار، المعاينات والموافقات، العقود والفواتير والمدفوعات، التنفيذ والتسليم والاستضافة والدومينات والدعم والتقارير والسجلات. تطبيق أقل صلاحية مع سجل تدقيق.

## شروط القبول غير القابلة للتنازل
- عرض المساعد والباقات والتسعير والكتالوج من أول زيارة مع انتقال المستخدم بينهما.
- أسعار حقيقية قابلة للتحقق بندًا بندًا، مع اختلاف صحيح عند تغيير الإضافات وطريقة الشراء.
- حفظ طلب العميل بعد التسجيل، ومعاينة مخصصة بالشعار والألوان والنصوص والإضافات.
- موافقة المعاينة ثم العقد ثم الدفع الموثق ثم التسليم الصحيح بحسب الاشتراك/شراء الكود.
- إمكانية إضافة قطاع/قالب وباقة وخاصية من الإدارة دون إعادة بناء الواجهة.
- اختبارات typecheck, lint, build, API, integration, pricing, browser/mobile, security؛ لا يكفي نجاح TypeScript وحده.
- الحفاظ على ميزات Stage40 وعدم حذفها عند تحسين تصميم V2، وعدم وصف النماذج التجريبية بأنها إنتاجية.
- عدم تفعيل أي تكامل إنتاجي دون موافقة صاحب المشروع.

## ترتيب البناء
1. جرد وفحص Stage40 والملفات الأصلية.
2. توحيد الكتالوج والباقات وقواعد التسعير والاختبارات.
3. مساعد الزائر وتكوين الطلب.
4. التسجيل والمعاينة المخصصة.
5. العقود والدفع والتسليم باستخدام محاكاة متحققة.
6. مراجعات التصميم والموبايل والفحوص.
7. بعد الاعتماد فقط: ربط الدومين والاستضافة والباك إند والبيانات وn8n والمزودين.
